# Client Requirements: Software Project Planning

**Dataset:** `nasa93dem.csv`  
**Client:** Engineering planning manager

| # | Customer ask | Skill |
|---:|---|---|
| 1 | Summarize the historical projects and their delivery outcomes. | remember |
| 2 | Find projects that delivered unusually much code for their effort. | remember |
| 3 | Estimate effort before approving a new project proposal. | guess |
| 4 | Predict likely defects and development time from project characteristics. | guess |
| 5 | Tell us whether one process is genuinely less costly than another. | certify |
| 6 | Tell us whether a predicted improvement is larger than historical noise. | certify |
| 7 | Assess project proposals as they arrive during portfolio planning. | flow |
| 8 | Update the recommendation when new project evidence becomes available. | flow |
| 9 | Explain which project factors are associated with excessive effort. | blame |
| 10 | Explain which factors are associated with defect risk. | blame |
| 11 | Justify an estimate to a skeptical project sponsor. | justify |
| 12 | Explain the trade-off between effort, time, defects, and delivered code. | justify |
| 13 | Choose project settings that maximize delivered value under a fixed budget. | choose |
| 14 | Choose a project plan that balances schedule and defect risk. | choose |
| 15 | Recommend the cheapest process change that reduces estimated risk. | fix |
| 16 | Suggest a repair for a proposal likely to exceed its effort budget. | fix |
| 17 | Spot a project record that looks inconsistent with the historical data. | spot |
| 18 | Flag a proposal whose predicted outcome is unusually uncertain. | spot |
| 19 | Compare our estimator against a simple historical-baseline estimator. | race |
| 20 | Determine whether the recommended planning policy wins across repeated samples. | race |
