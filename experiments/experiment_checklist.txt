SHRINKING-CODE EXPERIMENT — TREATMENT PROMPTS
===============================================

Use one fresh chat/context for every treatment trial and every ladder step.
Reuse is an explicit prompt instruction, never hidden conversation memory.

Every treatment runs the same ten skills across the same three domains:
remember, guess, certify, flow, blame, justify, choose, fix, spot, race.


TREATMENT 1 — LLM / PLAIN PYTHON / NO REUSE
============================================

Do:
- Use plain Python only.
- Use a fresh chat for every step and trial.
- Give the current domain, dataset schema, skill, and one requirement.
- Save prompt, response, code, tests, errors, and metrics.

Do not:
- Do not instruct reuse.
- Do not provide previous generated skill code as reusable architecture.
- Do not use scikit-learn or ezr.
- Do not use another treatment's output.

Prompt:

You are running Treatment 1 of a controlled experiment.
Treatment: LLM, plain Python, no reuse.
Domain: [DOMAIN]
Dataset: [DATASET]
Skill: [SKILL]
Requirement: [REQUIREMENT]

Use only the Python standard library. Implement this skill independently.
Do not reuse or assume any previous skill, architecture, or generated code.
Return complete source code, tests, and one run command. State assumptions and
limitations.

INPUTS FOR EVERY PROMPT
=======================

Paste only the relevant inputs:

- Treatment number and condition.
- Trial number.
- Domain and dataset.
- One customer requirement from docs/requirements/.
- Current skill name.
- Dataset schema and allowed background.
- Previous skill code only for reuse-instructed treatments.

Save each run under:

experiments/runs/treatmentN/trials/trialM/domain/stepK/

Save:

- prompt.txt
- response.txt
- generated source code
- tests and test output
- runtime output
- errors
- total LOC
- new LOC
- reused LOC
- quality metrics

The reuse pairs (2, 4, and 6) use fresh chats too. Their reuse condition is
created by explicitly pasting previous code into the prompt, not by allowing
the chat to remember it.
