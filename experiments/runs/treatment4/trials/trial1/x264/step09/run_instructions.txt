--top controls text display only. anomalies.json always contains every record
and all flags. --neighbors and --multiplier change the screening method;
they must be chosen as heuristics, not interpreted as calibrated error rates.
The API is spot.screen(Measurements, neighbors=10, multiplier=3.0), with
spot.render_text(report, top=10). All outputs describe historical screening.
No confirmed error labels, causal conclusions or detection-accuracy claims.

run_validation.py checks that copied source/tests remain byte-identical to
the allowed Step 8 inputs and that the dataset's SHA256 remains unchanged.
It captures each exact subprocess command, exit code, stdout, stderr and
wall time. test_output.txt captures unittest output; runtime_output.txt
captures all nine demos; regression_demos/ contains the old demo reports.
validation.json and metrics.csv store measured values. runtime_seconds is
only the spot.py subprocess wall time, including startup and JSON/text I/O.
Test and individual regression-demo timings appear separately in notes.

LOC counts nonblank, non-comment-only lines including docstrings in source/
only. new_loc counts insert/replace new-side application lines against the
allowed Step 8 source; unmodified files contribute zero new lines. Tests,
run_validation.py, installed libraries and all reports are excluded.

Validation history: validation_history/initial holds the first passing
86-test run. validation_history/evidence_update holds the subsequent passing
89-test run. Its passed-count metadata undercounted verbose output lines
(82 rather than 89); the final runner uses unittest's summary count instead.
No test or demo execution failed; this was a reporting correction. Neither
historical output was deleted. No dependency or prior-step changes occurred.
